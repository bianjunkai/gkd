# 本地 MVP 实现决策

记录日期：2026-09-08。此文件记录代码实际取舍，不把 PRD 的 V1 建议蓝图自动视为已完成。

## 1. 客户端与运行形态

微信小程序仍是主入口，使用原生 TypeScript/WXML/WXSS；增加 React Web 工作台用于本地体验和自动回归。两者共用 `packages/client`，没有以 WebView 替代原生页面。未提供 AppID，官方工具与真机体验尚未验证。

当前服务为模块化单体：FastAPI 进程内运行一个持久队列 worker 线程。每个 DATA_ROOT 通过操作系统文件锁限制一个服务进程，同 Workspace 的写入串行执行。外部模型调用不持有 Workspace 文件写锁。不能以增加 Uvicorn workers 的方式横向扩容。

## 2. 存储与一致性

本地默认 SQLite + SQLAlchemy；保留 PostgreSQL 配置入口，但未安装或测试该驱动。当前使用建表初始化，没有 Alembic 迁移、PostgreSQL 独立 worker 或生产部署脚本。

- Task/Group 内容：新增和任务写入使用格式 2，正文 `gtd:task:start/end` 任务块为权威，Front Matter 保存组属性。旧格式 1 仍按 Front Matter `tasks` 读取；打开、启动或重建索引不批量改写。完整混合块编辑界面尚未全部接通。
- Capture 原文：开放 JSON 文件先持久化，再登记数据库；client_capture_id 防重，启动恢复独立隔离损坏记录。
- 不可丢弃的元数据：身份、目录、提案、幂等/变更、任务队列与审计，必须随数据库备份。
- 安全 YAML：PyYAML 安全加载，加重复键、别名、标签和嵌套检查。未知合法字段和非托管正文保留；不承诺注释、空白与引号样式的无损往返。

多文件 Change Set 先固定版本对象和日志，再应用文件与索引；故障后恢复到批次前状态。重复提交返回原结果，版本/内容哈希/目标路径不一致时拒绝覆盖。撤销产生更大的新 revision，不倒退历史；后续已有编辑则使用版本预览恢复。

命名和路径同时考虑 Windows 与 POSIX 限制，拒绝越界、软链接、目录联接和危险 YAML。现有本机软链接创建受限，相应实际文件用例跳过，ZIP 链接防护已单独验证。

## 3. 整理与确认

默认引擎为明确标识的确定性本地规则，覆盖常见行动和相对日期；不是通用语义模型，也没有“模型高置信自动写入”。当前提案只支持新建和追加；手工界面另支持属性、任务及正文更新。

2026-09-09 创建归属修正：任务标题不再默认成为文件标题；Task 必须写入 Workspace 根目录或文件夹中的主题任务组。用户指定目标优先，其次建议完整路径/完整名称唯一匹配的可写任务组；仅共享短关键词不自动选中。外部提取器须给出独立主题名，照抄任务标题时回退「日常任务」；本地无语义模型时直接使用这一中性容器。默认容器只在根目录自动复用。同名歧义必须澄清，确认页可选其他位置；同位置同名、未指定自定义文件名的新建建议复用可写组。所有结果仍经预览和确认写入，已有文件不批量改名。

Responses 外部适配器使用结构化输出约束，不授予模型工具或任意文件路径执行权。当前原文、参照时间、时区、用户明确选择的目标标题/标签是发送范围；候选检索不会自动上传其他文件正文。格式失败最多修正一次，网络失败通过 Job 最多尝试三次，全部外部请求消耗每日次数额度。

2026-09-12 为接入智谱 GLM 做了准备：智谱官方已支持 OpenAI Responses 协议（`https://open.bigmodel.cn/api/v1`，面向 Coding Plan 套餐），适配器无需更换协议。实测该网关在鉴权失败时返回 **HTTP 200 + `{"success":false,"code":…}` 错误信封**（无凭据 `code:1001`，无效密钥 `code:401`），若按信封解析会误判为输出格式无效并白白消耗一次修正额度。适配器因此先识别该信封：`code` 为 401/1001 归为 `AI_AUTH_FAILED`，其余归为 `AI_REQUEST_REJECTED`，不进入格式修正重试，供应商错误码记入审计事件 `provider_code`（不向页面透出供应商原文）。模型或地址变更仍需工作空间重新授权。首次真实密钥调用尚未发生；严格 JSON Schema 在该端点的实际支持情况待真实调用验收。

提案修订绑定稳定动作 ID、文件和目录快照。用户选择动作、核对预览并确认后，才进入统一写入引擎。撤销/拒绝一份提案会参考同 Capture 的其他有效提案，避免误报“未处理”。

已按 OpenAI Docs 技能尝试查核官方接口资料，但当前网络没有成功取得官方页面；本次未配置真实密钥。模拟响应测试只证明本地适配协议和失败边界，真实接口兼容性、供应商政策及效果必须另行验收。

## 4. 搜索、内容可携与备份

查询使用参数化索引和中文子串匹配，不依赖外部向量服务或 pg_trgm。索引重建会报告损坏/重复文件，保留权威内容和回收站元数据；规模性能未压测。

2026-09-10 删除导出：原先的异步导出 Job、ZIP 打包、`/api/exports` 与鉴权下载接口、两端下载入口及相关测试已移除。触发原因是浏览器端 `fetch()` 下载长期只能得到 0 字节，定位后确认 Chromium 会把带 `Content-Disposition: attachment` 的响应转为下载事件并向页面返回合成的 204 空响应；但真正结论是该功能本身多余——Task/Group 已是工作目录中的 Markdown，Capture 已是 captures 中的开放 JSON，打包下载只是把已有可读文件再包一层，对 GTD 使用场景没有价值。因此不再提供面向用户的导出/下载，`storage` 目录段位减少 `exports`，新建工作空间不再创建该目录，备份不包含它。

内容可携形态即工作目录本身：用户可用任意编辑器或文件管理器直接取用、复制和备份。系统备份独立提供停服 SQLite 命令，使用 SQLite backup API 连同内容文件形成包，不直接复制可能遗漏 WAL 的主数据库文件。恢复只进入新目录，校验通过后生效并撤销旧会话。

备份未加密、无自动调度，且要求备份期间不发生外部文件编辑。它验证可恢复性，不等同于 V1 的在线共同快照、独立故障域、留存策略或 RPO/RTO。
